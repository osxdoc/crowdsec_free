# CrowdSec without the console: Docker Compose stack

One image contains the engine, `cscli`, the web UI (`cswebui`) and the
blocklist server (`csblocklistd`); Compose runs them as separate services that
share a configuration directory and a data directory.

```
            ┌────────────────────────────┐
 browser ──►│ cswebui         :8081      │──┐
            └────────────────────────────┘  │ edits ./config, reads the DB,
                                            │ scrapes metrics, admin API
            ┌────────────────────────────┐  │
 bouncers ─►│ crowdsec (LAPI)  :8080     │◄─┘
            │ metrics          :6060     │
            └──────────────┬─────────────┘
                           │ CAPI v3 (signals / decisions)
            ┌──────────────▼─────────────┐
 engines ──►│ csblocklistd     :8082     │
            └────────────────────────────┘
```

## Quick start (on the target host)

```sh
git clone <your-fork-url> crowdsec-free
cd crowdsec-free/deploy/docker
cp .env.example .env      # set WEBUI_ADMIN_PASSWORD and BLOCKLIST_ADMIN_TOKEN

docker compose up -d --build
docker compose logs -f bootstrap   # first start: credentials, hub/GeoIP download
```

Then open `http://127.0.0.1:8081` and log in as `admin`. The UI is bound to
localhost by default; set `WEBUI_BIND=0.0.0.0` in `.env` to reach it from
elsewhere, behind a TLS proxy.

Provisioning runs in two idempotent one-shot services:

1. `bootstrap` (before the blocklist server) writes the default configuration
   into `./config` (existing files are kept), generates the admin password and
   blocklist token, registers the agent and UI machines directly in the SQLite
   database, and installs `HUB_COLLECTIONS` plus GeoLite2 data (needed for the
   Geo page and the world map).
2. `register` (after the blocklist server is healthy) subscribes the engine to
   `csblocklistd` and writes `online_api_credentials.yaml`.

The engine starts once both are done.

## Building without a source tree on the host

The Quick Start builds from the checkout you cloned. If you develop somewhere
else and only want to run the stack here, push first and let the host build the
commit it is going to run:

```sh
curl -fsSL https://raw.githubusercontent.com/<owner>/crowdsec_free/master/deploy/docker/build-image.sh \
  | sh -s -- <commit-ish> v1.8.2
docker compose up -d            # no --build: the image already exists
```

`build-image.sh` fetches the archive of that commit from GitHub, builds it in a
temporary directory and removes it, so nothing is kept on the host. Images are
native to the architecture of the machine that builds them, so run the script
where the containers run. The second argument is the version string compiled
into the binaries and the image tag: it has to match `CROWDSEC_VERSION` in
`.env`. Drop the `build:` block from your compose file in this mode, otherwise a
later `up -d --build` fails on the missing build context.

## Log sources

`crowdsec` mounts the host's `/var/log` at `/host/var/log` (read-only). Add the
files you want to parse in `config/acquis.yaml`:

```yaml
filenames:
  - /host/var/log/auth.log
  - /host/var/log/nginx/access.log
labels:
  type: syslog    # nginx: type: nginx
```

Then reload the engine (Configuration page → "Reload engine", or
`docker compose restart crowdsec`). For journald, mount the journal socket and
use `source: journalctl`.

## Other engines

Engines that should share your blocklist only need a different CAPI URL:

```sh
cscli capi register --url http://<host>:8082/ -f /etc/crowdsec/online_api_credentials.yaml
systemctl reload crowdsec
```

By default only manual bans (`origin: cscli`) are shared. Set
`share_manual_decisions: true` in `console.yaml` on those engines; raise
`push.accept_origins` in `config/blocklist.yaml` to also share scenario hits.

Bouncers on the same host (or in the host network) reach the LAPI on
`127.0.0.1:8080` and appsec on `127.0.0.1:7422`; set `LAPI_BIND`/`APPSEC_BIND`
to `0.0.0.0` for bouncers on other hosts. Add their source addresses to
`api.server.trusted_ips` (admin operations) and register them with
`docker compose exec crowdsec cscli bouncers add <name>`.

## Configuration

Everything lives in `./config` and is mounted into the containers:

| File | Purpose |
| ---- | ------- |
| `config.yaml` | engine, LAPI listen address, DB, Prometheus, trusted IPs |
| `acquis.yaml` | log sources |
| `profiles.yaml`, `console.yaml` | decisions and what is shared with the blocklist |
| `webui.yaml` | UI accounts, editable files, data sources, blocklist admin token |
| `blocklist.yaml` | blocklist server, push filters |
| `local_api_credentials.yaml`, `cswebui_credentials.yaml`, `online_api_credentials.yaml` | generated by bootstrap, keep private |

Files in `webui.yaml` under `files:` are editable from the UI. The Hub page installs,
removes and upgrades hub items, and reloads the engine after each change with
`pkill -HUP` through the shared PID namespace.

State that is not configuration lives in `./data` (`crowdsec.db`, GeoIP
databases). `.env` selects ports, their bind addresses (`LAPI_BIND`,
`APPSEC_BIND`, `WEBUI_BIND`, `BLOCKLIST_BIND`), `TZ` and `CROWDSEC_SUBNET`. A
deployment with its own compose file should change only the build source (the
context, or the whole `build:` block when the image comes from `build-image.sh`)
and the read-only log mounts, so `diff` against this template stays small otherwise.

## Operations

```sh
docker compose ps
docker compose logs -f cswebui
docker compose restart crowdsec          # changes made outside the UI
docker compose run --rm bootstrap config   # re-run config/credentials/hub
docker compose run --rm register           # re-run blocklist registration
docker compose pull && docker compose up -d --build   # upgrade
```

Backup: `docker compose stop crowdsec csblocklistd`, then archive `./config`
and `./data` — both are bind mounts next to the compose file.

## Security notes

- The UI is HTTP only and bound to `127.0.0.1` by default (`WEBUI_BIND`). Put a
  TLS reverse proxy in front of it (and set `secure_cookie: true`) before
  publishing it on the network.
- `:8080` (LAPI), `:7422` (appsec) and `:8082` (blocklist) are published on
  localhost by default. Drop the mappings entirely if all bouncers/engines run
  inside the compose network. The blocklist registration endpoint is
  unauthenticated by default, like the CAPI; restrict it with firewall rules or
  `registration_token`.
- The admin token protects `/admin/v1` on the blocklist server; the UI stores it
  in `webui.yaml`. Keep `config/` at mode `0700` if you care about tokens.
- `bootstrap` replaces the placeholder in `config/webui.yaml` (password hash) and
  `config/blocklist.yaml` (admin token). Those two files are tracked, so running the
  stack from inside the clone dirties the repository with real secrets: keep the
  deployment elsewhere, and run `scripts/leak-check.sh` before you push.
- `config.yaml` trusts `172.28.0.0/16` so the UI container may delete alerts.
  If you change `CROWDSEC_SUBNET`, update `trusted_ips` too.

## Troubleshooting

| Symptom | Fix |
| ------- | --- |
| UI says `password_hash is not a bcrypt hash` | bootstrap did not run; `docker compose run --rm bootstrap config` and restart `cswebui` |
| `docker compose logs bootstrap` shows hub download errors | offline host; set `SKIP_HUB_UPDATE=true`, mount an existing `hub/` directory |
| No GeoIP data (empty country/AS) | run bootstrap with hub content (`SKIP_HUB_UPDATE=false`), check `./data` for `GeoLite2-City.mmdb` |
| No alerts | check `acquis.yaml` paths and `docker compose logs crowdsec`; the host `/var/log` must contain the files |
| Engine exits with CAPI auth errors | blocklist DB was reset: delete `config/online_api_credentials.yaml` and re-run bootstrap |
| `Reload engine` fails | ensure `pid: "service:crowdsec"` is still set for `cswebui` |
